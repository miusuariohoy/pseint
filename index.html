1 Programación Estructurada

Programar es escribir una lista ordenada de instrucciones para que una computadora resuelva un problema. La computadora no adivina: hace exactamente lo que le indicamos, paso por paso.

🍳 Ejemplo cotidiano: una receta de cocina es un algoritmo. Tiene datos (ingredientes), pasos en orden (secuencia), decisiones (“si hay café, serví café; si no, serví té”) y repeticiones (“revolvé hasta que hierva”).
Idea clave Programar = dar instrucciones ordenadas para resolver un problema

Cuando el programa se arma combinando solo tres estructuras de control, hablamos de programación estructurada. Así el código queda ordenado, se lee de arriba hacia abajo y es más fácil de corregir.

  • Secuencia: las instrucciones se ejecutan una después de otra, en el orden escrito.
  • Selección: el programa elige un camino según una condición (Si … Entonces … Sino … FinSi).
  • Iteración: un bloque se repite mientras se cumpla una condición (Mientras) o una cantidad fija de veces (Para).
Las tres se combinan Secuencia + Selección + Iteración

La receta del desayuno, escrita como algoritmo:

Algoritmo PrepararDesayuno
    Definir hayCafe Como Logico;
    Definir i Como Entero;
    hayCafe <- Verdadero;
    Escribir "Poner agua a calentar";          // Secuencia
    Si hayCafe Entonces                        // Selección
        Escribir "Servir café";
    Sino
        Escribir "Servir té";
    FinSi
    Para i <- 1 Hasta 2 Con Paso 1 Hacer       // Iteración
        Escribir "Untar una tostada";
    FinPara
FinAlgoritmo
  • Secuencia: primero se calienta el agua y después se sirve la bebida.
  • Selección: el Si elige café o té según hayCafe.
  • Iteración: el Para repite dos veces el untado de tostadas.

✍️ Actividad 1: ¿qué es programar?

¿Qué es programar?

  • A) Escribir instrucciones ordenadas para que una computadora resuelva un problema.
  • B) Encender la computadora y usar programas ya instalados.
  • C) Copiar código de internet sin entender qué hace.
  • D) Armar las partes físicas de la computadora.
✔ Correcta: A. Programar es dar instrucciones ordenadas. La computadora las ejecuta paso a paso; no decide por su cuenta.

✍️ Actividad 2: reconocer estructuras

¿Cuál de estas opciones es una estructura de iteración (repetición)?

  • A) Si … Entonces … FinSi
  • B) Definir edad Como Entero;

  • D) Escribir "Hola";

2 Variables

Una variable es un espacio con nombre en la memoria donde guardamos un dato que puede cambiar mientras el programa se ejecuta. Pensala como una caja rotulada: el rótulo es el nombre, el contenido es el valor y el tipo indica qué clase de dato puede guardar.

📦 Ejemplo cotidiano: una caja rotulada “edad” solo acepta números enteros; otra rotulada “nombre” acepta texto. Si intentás guardar "Juan" en la caja de la edad, el programa se confunde: el dato no corresponde al tipo.

En PSeInt cada variable se declara antes de usarse, indicando su tipo:

Sintaxis Definir nombre_variable Como Tipo_De_Dato;
Definir variable1, variable2 Como Tipo_De_Dato;

Tipos de datos que vas a usar:

  • Entero: números sin decimales, positivos, negativos o cero (20, -3, 0).
  • Real: números con parte decimal (1.75, 250.50, -0.5).
  • Caracter: texto entre comillas ("Ana", "Hola mundo", "4to").
  • Logico: solo dos valores posibles: Verdadero o Falso.

Declarar es crear la caja; asignar es guardar un valor dentro. La asignación se escribe con la flecha <-, no con = (el = se usa para comparar). 

Algoritmo DatosPersonales
    Definir nombre Como Caracter;
    Definir edad Como Entero;
    Definir altura Como Real;
    Definir activo Como Logico;

    nombre <- "Ana";        // texto entre comillas
    edad <- 20;             // número entero
    altura <- 1.65;         // número real
    activo <- Verdadero;    // valor lógico

    Escribir "Nombre: ", nombre;
    Escribir "Edad: ", edad, " años";
    Escribir "Altura: ", altura, " m";
    Escribir "Activo: ", activo;
FinAlgoritmo
  • Líneas 2 a 5: declaramos cuatro variables, cada una con el tipo que le corresponde.
  • Líneas 7 a 10: con <- guardamos un valor en cada caja. El texto va entre comillas; los números y los valores lógicos, no.
  • Líneas 12 a 15: mostramos los valores combinando texto fijo con variables.
  • También podés declarar varias variables del mismo tipo en una línea: Definir edad, cantidad Como Entero;.
🪪 Reglas para los nombres: no llevan espacios, no empiezan con un número y no pueden coincidir con palabras reservadas del lenguaje (Si, Mientras, Escribir, etc.). En PSeInt no se distinguen mayúsculas de minúsculas: Edad y edad son la misma variable. Usá nombres que expliquen qué guardan.

Errores comunes con variables:

  • Usar una variable sin declararla: PSeInt necesita saber de qué tipo es antes de usarla.
  • Asignar con = en lugar de <-: edad <- 20; guarda; edad = 20 compara.
  • Guardar un texto en una variable numérica o un decimal en una variable Entero.
  • Confundir declarar con asignar: después de Definir edad Como Entero; la variable existe, pero todavía no tiene un valor elegido por vos.

✍️ Actividad 1: tres variables

Declará tres variables: nombre (Caracter), edad (Entero) y altura (Real). Asignales un valor a cada una y mostralas con Escribir.

✍️ Actividad 2: declarar una constante

En PSeInt no hay una palabra especial para las constantes: se usa una variable a la que se le asigna un valor una sola vez y no se modifica. Declará PI como Real, asignale 3.1416 y mostrala con Escribir.

3 Leer y Escribir

Son los comandos de entrada y salida. Escribir muestra información en pantalla (salida) y Leer pausa el programa para capturar un dato escrito por el usuario (entrada). Son lo primero que necesitás para que un programa se comunique con quien lo usa.

Salida Escribir "texto", variable, otra_variable;

Entrada Leer variable;
  • El texto literal va entre comillas dobles: "Hola". Las variables van sin comillas: nombre.
  • Las comas separan las partes que se muestran juntas en una misma línea. Escribir agrega un salto de línea al final.
  • Leer no muestra ningún mensaje por sí solo: por eso antes se escribe una pregunta o indicación con Escribir.
  • El dato que se lee debe coincidir con el tipo de la variable: si edad es Entero, el usuario debe escribir un número entero.
Algoritmo EntradaSalida
    Definir nombre Como Caracter;
    Definir edad Como Entero;

    Escribir "Escribí tu nombre:";
    Leer nombre;                       // Guarda lo que el usuario tipea

    Escribir "Escribí tu edad:";
    Leer edad;

    Escribir "Hola, ", nombre, ". Tenés ", edad, " años.";
FinAlgoritmo
  • Línea 5: muestra la pregunta para que el usuario sepa qué escribir.
  • Línea 6: pausa la ejecución y guarda la respuesta del teclado en nombre.
  • Líneas 8 y 9: el mismo esquema para la edad: primero preguntar, después leer.
  • Línea 11: combina texto fijo, variables y más texto. Las comas permiten armar una oración completa sin cortar la línea.
💡 Tip: si querés mostrar algo sin saltar de línea, PSeInt permite Escribir Sin Saltar "...". Es útil para armar tablas o pedir un dato en la misma línea. Para el apunte alcanza con Escribir y Leer.

Errores comunes con Leer y Escribir:

  • Poner comillas en el Leer: Leer "nombre" está mal; se escribe Leer nombre;.
  • Olvidar las comillas en un texto fijo: Escribir Hola se interpreta como una variable; lo correcto es Escribir "Hola";.
  • Leer sin mostrar una indicación: el usuario ve una pantalla vacía y no sabe qué escribir.
  • Leer un texto en una variable numérica o viceversa: el dato debe respetar el tipo.
  • Olvidar el punto y coma al final de cada instrucción.

✍️ Actividad 1: pedir y mostrar

Pedile al usuario su ciudad y mostrá el mensaje Vivís en <ciudad>. Usá Leer para capturar el dato y luego Escribir para mostrarlo.

✍️ Actividad 2: sumar dos números leídos

Declará dos variables Entero, pedí dos números con Escribir, capturalos con Leer y mostrá el resultado de la suma.

4 Condicionales (Si–Entonces)

Un condicional permite tomar decisiones: se evalúa una condición y, según sea verdadera o falsa, se ejecuta un camino u otro. Es la estructura de selección: el programa deja de ser una línea recta y elige.

🚦 Ejemplo cotidiano: “Si está lloviendo, llevá paraguas; si no, llevá gorra”. La condición se revisa una vez y se elige un solo camino.
Sintaxis completa Si condición Entonces
    // instrucciones si la condición es verdadera
Sino
    // instrucciones si la condición es falsa
FinSi

La condición es una expresión que da como resultado Verdadero o Falso. Se arma con operadores de comparación:

  • = igual que (algunas versiones también aceptan ==)  ·  <> distinto de (algunas versiones también aceptan !=).
  • > mayor que  ·  < menor que.
  • >= mayor o igual que  ·  <= menor o igual que.
  • Se pueden combinar con los operadores lógicos Y, O y NO: Si edad >= 18 Y tieneEntrada Entonces.
Algoritmo EjemploCondicional
    Definir nota Como Real;
    nota <- 7.5;
    Si nota >= 6.0 Entonces
        Escribir "Aprobado";
    Sino
        Escribir "Desaprobado";
    FinSi
FinAlgoritmo
  • Línea 4: evalúa si nota (7.5) es mayor o igual a 6.0. El resultado es Verdadero.
  • Línea 5: como la condición fue verdadera, se ejecuta esa línea y se salta el Sino.
  • Si la nota hubiera sido 4, la condición daría Falso y se ejecutaría solamente la línea del Sino.

El Sino es opcional: si solo querés hacer algo cuando la condición se cumple, alcanza con Si … Entonces … FinSi. Para elegir entre más de dos caminos, se anidan condicionales: 

Algoritmo ClasificarNota
    Definir nota Como Real;
    Escribir "Ingresá la nota:";
    Leer nota;

    Si nota >= 9 Entonces
        Escribir "Excelente";
    Sino
        Si nota >= 6 Entonces
            Escribir "Aprobado";
        Sino
            Escribir "Desaprobado";
        FinSi
    FinSi
FinAlgoritmo
  • Primero se pregunta si la nota es 9 o más. Si es así, muestra “Excelente” y no revisa el resto.
  • Si no, entra al Sino y hace una segunda pregunta: ¿es 6 o más?
  • Cada Si abierto necesita su propio FinSi. Por eso quedan dos FinSi al final.

Errores comunes con condicionales:

  • Olvidar Entonces después de la condición.
  • Olvidar FinSi o cerrar menos bloques de los que se abrieron.
  • Usar = para asignar dentro del condicional: para guardar se usa <-; = solo compara.
  • Poner punto y coma después de Entonces o de Sino: no van.
  • Confundir Sino con Sino Si: en PSeInt el Sino no lleva condición; si necesitás otra pregunta, anidá un nuevo Si.

✍️ Actividad 1: mayor o menor de edad

Leé la edad de una persona. Si es mayor o igual a 18, mostrá "Mayor de edad"; si no, mostrá "Menor de edad". Usá Si … Entonces … Sino … FinSi.

✍️ Actividad 2: positivo, negativo o cero

Leé un número. Si es mayor a 0, mostrá "Positivo"; si es menor a 0, mostrá "Negativo"; si es igual a 0, mostrá "Cero". Usá Si anidados y cerrá cada uno con FinSi.

5 Contador

Un contador es una variable que aumenta o disminuye siempre en una cantidad fija (normalmente 1). Sirve para responder cuántas veces ocurre algo: cuántos aprobaron, cuántos productos se cargaron, cuántos números cumplen una condición.

📦 Es una variable: por eso primero se declara indicando su tipo (Definir c Como Entero;) y después se le define su valor inicial (c <- 0;). Sin declaración no existe; sin valor inicial no se sabe desde qué número empezar a contar.
Fórmula clásica contador <- contador + 1;

Todo contador se usa en estos pasos:

  • 1. Declarar la variable: Definir c Como Entero;.
  • 2. Definir el valor inicial antes de contar: c <- 0; (0 es lo habitual para contar ocurrencias).
  • 3. Incrementar cuando ocurre el evento que querés contar: c <- c + 1;.
  • 4. Mostrar el resultado: Escribir "Total: ", c;.
Algoritmo EjemploContador
    Definir c Como Entero;
    c <- 0;          // Valor inicial: todavía no conté nada
    c <- c + 1;      // Ahora vale 1
    c <- c + 1;      // Ahora vale 2
    Escribir "Contador: ", c;
FinAlgoritmo
  • Línea 2: declaramos la variable c como Entero.
  • Línea 3: le damos el valor inicial 0: “todavía no conté nada”.
  • Líneas 4 y 5: sumamos 1 al valor actual. Primero pasa a 1 y después a 2.
  • Línea 6: mostramos el total acumulado en el contador.

También se puede contar solo los casos que cumplen una condición. Acá no hay bucles: se usan tres condicionales y el contador aumenta únicamente cuando la condición es verdadera. 

Algoritmo ContarAprobados
    Definir nota1, nota2, nota3, aprobados Como Entero;
    nota1 <- 8;
    nota2 <- 4;
    nota3 <- 10;
    aprobados <- 0;                 // 1) valor inicial

    Si nota1 >= 6 Entonces
        aprobados <- aprobados + 1; // 2) contar si cumple
    FinSi

    Si nota2 >= 6 Entonces
        aprobados <- aprobados + 1;
    FinSi

    Si nota3 >= 6 Entonces
        aprobados <- aprobados + 1;
    FinSi

    Escribir "Aprobados: ", aprobados;   // 3) mostrar
FinAlgoritmo
  • aprobados empieza en 0 y aumenta de a 1 por cada nota que llega a 6.
  • Al terminar los tres Si, el contador contiene la cantidad total.
  • Más adelante, cuando veas los bucles, vas a repetir este mismo incremento dentro de un Para o un Mientras para contar muchos datos.
💡 ¿0 o 1? Si tu objetivo es contar ocurrencias (cuántos hay), empezá en 0. Si querés numerar elementos (1.º, 2.º, 3.º…), podés empezar en 1 y decidir si incrementás antes o después de mostrar. Para un conteo, arrancar en 1 suma uno de más y el resultado queda mal.

Contador vs. acumulador (diferencia clave):

  • Contador: suma siempre lo mismo, generalmente 1. c <- c + 1;
  • Acumulador: suma un valor que cambia en cada operación. total <- total + precio;
  • El contador responde “¿cuántos?”; el acumulador responde “¿cuánto suman?”.

Errores comunes con contadores:

  • No declarar la variable antes de usarla.
  • Olvidar el valor inicial: en PSeInt estricto no podés sumar sobre una variable sin valor base.
  • Reiniciar el contador en medio del conteo: se pierde lo que ya se contó.
  • Incrementar fuera del condicional cuando solo querés contar algunos casos: termina contando todos.
  • Mostrar el contador antes de terminar cuando querés el total final: mostralo al final.

✍️ Actividad 1: contador sin bucles

Declará un contador como Entero, definí su valor inicial en 0, incrementalo 3 veces (sin usar Para ni Mientras) y mostrá el valor final con Escribir.

✍️ Actividad 2: contar aprobados sin bucles

Sin bucles: asigná nota1 <- 8;, nota2 <- 4; y nota3 <- 10;. Con tres Si, contá cuántas notas son mayores o iguales a 6 y mostrá el total.

6 Acumulador

Un acumulador es una variable que va sumando valores variables. Se usa para calcular totales: el total de una caja, la suma de notas, los gastos del mes, los puntos de un juego. La diferencia con el contador es que el valor que se suma no es fijo: puede ser el precio de cada producto o la nota de cada alumno.

📦 Es una variable: también se declara con su tipo (Definir total Como Real;) y se le define un valor inicial (total <- 0;). Si no se declara, PSeInt no sabe qué tipo de dato va a guardar; si no se inicializa, no hay una base para empezar a sumar.
Fórmula clásica acumulador <- acumulador + variable_o_valor;

El acumulador se usa en estos pasos:

  • 1. Declarar la variable: Definir total Como Real;.
  • 2. Definir el valor inicial en 0 para las sumas (en 1 solo si vas a multiplicar).
  • 3. Acumular el valor de cada operación al total anterior.
  • 4. Mostrar o usar el total cuando ya terminaste de sumar.
Algoritmo EjemploAcumulador
    Definir suma, precio Como Real;
    suma <- 0;              // Valor inicial obligatorio
    precio <- 15.50;
    suma <- suma + precio;  // Suma el precio variable
    Escribir "Total acumulado: ", suma;
FinAlgoritmo
  • Línea 2: declaramos suma y precio como Real.
  • Línea 3: el acumulador arranca limpio en 0.
  • Línea 5: suma el contenido de precio (15.50) a lo que ya tenía suma.
  • Línea 6: muestra el total acumulado.

Ejemplo sin bucles: una caja que suma los precios de tres productos. 

Algoritmo TotalDeCaja
    Definir precio1, precio2, precio3, total Como Real;
    precio1 <- 150.50;
    precio2 <- 200;
    precio3 <- 99.99;
    total <- 0;                         // 1) valor inicial
    total <- total + precio1;           // 2) acumular
    total <- total + precio2;
    total <- total + precio3;
    Escribir "Total a pagar: $", total;   // 3) mostrar
FinAlgoritmo
  • Cada línea suma un precio distinto al total anterior.
  • Al terminar, total contiene la suma de los tres precios.
  • El acumulador no se reinicia entre sumas: si lo hacés, solo guardarías el último precio.
  • Más adelante, cuando veas los bucles, vas a repetir la suma dentro de un Para o un Mientras para acumular muchos datos.

Contador y acumulador juntos: para calcular un promedio necesitás las dos cosas. 

Algoritmo PromedioDeNotas
    Definir nota1, nota2, nota3, suma, promedio Como Real;
    nota1 <- 7;
    nota2 <- 8;
    nota3 <- 9;
    suma <- 0;                          // acumulador
    suma <- suma + nota1;
    suma <- suma + nota2;
    suma <- suma + nota3;
    promedio <- suma / 3;               // el 3 es la cantidad de notas
    Escribir "Promedio: ", promedio;
FinAlgoritmo
  • suma acumula el total de las notas.
  • El promedio se calcula después de sumar: total dividido la cantidad de valores.
  • Si la cantidad de notas fuera variable, usarías además un contador (cantidad <- cantidad + 1) y dividirías por cantidad en lugar de por 3.
💡 Regla práctica: inicializá en 0 cuando sumás y en 1 cuando multiplicás. Un acumulador de suma que arranca en 1 da todos los resultados corridos en uno.

Errores comunes con acumuladores:

  • No declarar la variable o no indicar su tipo.
  • Inicializar en 1 una suma: el total queda siempre uno de más.
  • Reiniciar el acumulador en medio de las sumas: se pierde todo lo sumado antes.
  • Acumular la variable equivocada: sumar una nota repetida o sumar el contador en lugar del valor.
  • Dividir por cero al calcular un promedio cuando no se ingresó ningún valor.

✍️ Actividad 1: acumulador sin bucles

Declará un acumulador como Real, definí su valor inicial en 0 y sumale tres precios: 150.50, 200 y 99.99. Mostrá el total con Escribir. No uses Para ni Mientras.

✍️ Actividad 2: promedio sin bucles

Sin bucles: asigná nota1 <- 7;, nota2 <- 8; y nota3 <- 9;. Acumulá las tres notas, calculá el promedio dividiendo por 3 y mostralo.

7 Bucle Para (For)

El bucle Para repite un bloque un número exacto y conocido de veces. En la misma línea se indica dónde empieza el contador, dónde termina y de cuánto en cuánto avanza. PSeInt se encarga solo de inicializar, avanzar y cortar. Es el bucle que vas a usar cuando ya sabés cuántas vueltas necesita el programa (por ejemplo, mostrar del 1 al 10).

Sintaxis Para variable <- inicio Hasta fin Con Paso incremento Hacer
    // instrucciones que se repiten
FinPara
  • inicio: primer valor que toma la variable.
  • fin: último valor que puede tomar. El Hasta es inclusivo: si dice Hasta 3, se ejecuta también la vuelta 3.
  • Con Paso: cuánto aumenta la variable en cada vuelta. Si se omite, PSeInt usa 1.
  • Con paso negativo el bucle cuenta hacia atrás: Para i <- 5 Hasta 1 Con Paso -1 Hacer.
Algoritmo EjemploPara
    Definir i Como Entero;
    Para i <- 1 Hasta 3 Con Paso 1 Hacer
        Escribir "Vuelta número: ", i;
    FinPara
FinAlgoritmo
  • Línea 3: i empieza en 1, se detiene al superar 3 y avanza de 1 en 1. Da exactamente 3 vueltas.
  • Línea 4: muestra el número de la vuelta actual: 1, 2 y 3.

Ejemplos útiles:

Algoritmo TablaDelDos
    Definir i Como Entero;
    Para i <- 1 Hasta 5 Con Paso 1 Hacer
        Escribir "2 x ", i, " = ", 2 * i;
    FinPara
FinAlgoritmo
Algoritmo CuentaRegresiva
    Definir i Como Entero;
    Para i <- 5 Hasta 1 Con Paso -1 Hacer
        Escribir i;
    FinPara
    Escribir "¡Despegue!";
FinAlgoritmo
  • Tabla del 2: la variable i también se puede usar dentro de una operación, no solo para mostrar.
  • Cuenta regresiva: con Con Paso -1 el contador baja de 5 a 1. El signo del paso debe acompañar la dirección.
⚠️ No modifiques la variable del bucle por dentro. Si dentro de un Para i <- 1 Hasta 5 escribís i <- i + 2, el control del bucle se rompe y puede saltarse vueltas o no terminar nunca. Para el control manual existe otro bucle, Mientras, que vas a ver en el tema siguiente.

Errores comunes con Para:

  • Olvidar FinPara o el Hacer.
  • Usar Con Paso 0: el contador nunca avanza y el bucle se vuelve infinito.
  • Esperar que Hasta no incluya el último valor: Hasta 10 sí incluye el 10.
  • Elegir mal el paso: para los pares del 2 al 10 conviene Con Paso 2; para contar de uno en uno, Con Paso 1.
  • Repetir la declaración de la variable del bucle dentro del Para: se declara antes, con Definir.

✍️ Actividad 1: pares del 2 al 10

Mostrá los números pares del 2 al 10 usando un bucle Para. Podés usar Con Paso 2 o recorrer todo y filtrar con Si + MOD.

✍️ Actividad 2: cuenta regresiva

Mostrá una cuenta regresiva del 5 al 1 usando un bucle Para con Con Paso -1. Al terminar, mostrá "¡Despegue!" con Escribir.

8 Bucle Mientras

El bucle Mientras repite un bloque de instrucciones mientras una condición sea verdadera. La condición se revisa antes de cada vuelta: si es falsa desde el principio, el bloque no se ejecuta ninguna vez. Se puede usar de dos formas:

  • Repetición por condición: no sabemos de antemano cuántas vueltas habrá; el bucle termina cuando la condición deja de cumplirse (un menú hasta elegir 0, una validación hasta ingresar un dato correcto, leer hasta que el usuario decida salir).
  • Repetición fija con contador: sabemos cuántas vueltas queremos, pero elegimos controlarlas a mano con un contador: lo inicializamos antes, lo comparamos en la condición y lo incrementamos dentro del bucle para contar exactamente, por ejemplo, del 1 al 5.
Sintaxis Mientras condición Hacer
    // instrucciones que se repiten
FinMientras
🔁 Idea clave: todo Mientras necesita tres piezas coordinadas: inicializar la variable antes del bucle, evaluar una condición que en algún momento se vuelva falsa y actualizar esa variable dentro del bucle. Si falta la actualización, el bucle nunca termina (bucle infinito).

Ejemplo con un menú: el programa sigue mostrando opciones hasta que el usuario escriba 0. Como no sabemos cuántas veces va a elegir, usamos Mientras. 

Algoritmo EjemploMientras
    Definir opcion Como Entero;
    opcion <- 1;
    Mientras opcion <> 0 Hacer
        Escribir "Para salir presioná 0; para continuar, cualquier número:";
        Leer opcion;
    FinMientras
    Escribir "Programa finalizado.";
FinAlgoritmo
  • Línea 3: inicializamos opcion en 1 para que la condición sea verdadera la primera vez y el bucle entre.
  • Línea 4: revisa si opcion es distinto de 0. Como vale 1, entra al bloque.
  • Línea 6: pide un nuevo valor. Ese Leer es lo que permite que la condición cambie: cuando el usuario escribe 0, el bucle termina.
  • Línea 8: se ejecuta una sola vez, cuando el bucle ya terminó.

Repetición fija con contador: las dos formas de contar del 1 al 5

Acá el número de vueltas es fijo (5), pero el control lo hace el contador c. La inicialización depende de dónde pongas el incremento. Las dos versiones muestran 1 2 3 4 5; elegí la que te resulte más clara.

Opción 1 · Contador en 0, incremento al principio 
Algoritmo ContarConCero
    Definir c Como Entero;
    c <- 0;                 // arranca en 0
    Mientras c < 5 Hacer    // se repite mientras c sea menor que 5
        c <- c + 1;         // primero incrementa: 1, 2, 3, 4, 5
        Escribir c;         // después muestra el valor
    FinMientras
FinAlgoritmo
Opción 2 · Contador en 1, incremento al final 
Algoritmo ContarConUno
    Definir c Como Entero;
    c <- 1;                 // arranca en 1
    Mientras c <= 5 Hacer   // se repite mientras c no supere 5
        Escribir c;         // muestra 1, 2, 3, 4, 5
        c <- c + 1;         // incrementa al final de cada vuelta
    FinMientras
FinAlgoritmo
⚠️ Cuidado con la condición: si arrancás en 0, incrementás antes de mostrar y usás Mientras c <= 5, el contador llega a 6 y se muestra 1 2 3 4 5 6. Para mostrar exactamente hasta 5, la condición debe ser c < 5 (o c <= 4). En cambio, si arrancás en 1 e incrementás al final, c <= 5 es la condición correcta.

Las dos inicializaciones son válidas: 0 o 1. Lo que no puede faltar es que la condición y el incremento estén en el lugar correcto.

Ejemplo de bucle infinito (para reconocerlo):

Algoritmo BucleInfinito
    Definir c Como Entero;
    c <- 0;
    Mientras c < 5 Hacer
        Escribir c;      // falta c <- c + 1: c nunca cambia
    FinMientras
FinAlgoritmo
  • La condición c < 5 siempre da verdadero porque c queda en 0 para siempre.
  • El programa se queda mostrando 0 sin parar. La solución es actualizar el contador dentro del bucle.

¿Cuándo usar Mientras y cuándo Para?

  • Mientras por condición: no sabés cuántas vueltas serán (menú, leer hasta 0, validar un dato hasta que sea correcto).
  • Mientras por contador: sabés cuántas vueltas querés, pero preferís controlar el contador y el incremento a mano.
  • Para: sabés la cantidad exacta de vueltas y querés que PSeInt maneje el contador automáticamente (mostrar del 1 al 10, recorrer 5 productos).

Errores comunes con Mientras:

  • No incrementar la variable dentro del bucle → bucle infinito.
  • Incrementar fuera del bucle (antes o después del FinMientras) → la condición nunca cambia.
  • Inicializar dentro del bucle → el contador vuelve siempre al mismo valor.
  • Olvidar Hacer o el FinMientras.
  • Usar = en la condición cuando querés comparar; recordá que = compara y <- asigna.

✍️ Actividad 1: repetición fija (contar hasta 5)

Mostrá los números del 1 al 5 usando un bucle Mientras. Podés inicializar el contador en 0 (incrementando al principio) o en 1 (incrementando al final). No olvides incrementar la variable dentro del bucle para que no se repita infinitamente.

✍️ Actividad 2: repetición por condición (validar una edad)

Pedí una edad y repetí con Mientras mientras sea menor a 0 o mayor a 120. Dentro del bucle, mostrá un mensaje de error y volvé a Leer la edad. Al salir, mostrá la edad válida. Usá Mientras … Hacer … FinMientras.

9 Subprocesos / Funciones

Un subproceso es un bloque de código con nombre propio que realiza una tarea específica. El procedimiento es un subproceso que NO devuelve un valor: solo ejecuta acciones (mostrar un menú, imprimir un recibo, validar datos). Se usa para modularizar: dividir un programa grande en piezas chicas, reutilizables y fáciles de leer.

🧩 ¿Para qué modularizar?
  • Reutilizar: escribís una vez el saludo y lo llamás todas las veces que haga falta.
  • Ordenar: el algoritmo principal queda corto y se entiende de un vistazo.
  • Corregir: si hay un error en el recibo, lo arreglás en un solo lugar.
  • Probar: podés revisar cada pieza por separado antes de unir todo.
Sintaxis general SubProceso NombreDelProcedimiento (parámetro1, parámetro2)
    // acciones del procedimiento
FinSubProceso

// Para usarlo (llamarlo):
NombreDelProcedimiento(valor1, valor2);
⚠️ Idea clave: los parámetros son los datos que le "pasás" al procedimiento entre paréntesis. Un procedimiento puede tener 0, 1 o varios parámetros. Las variables declaradas dentro del subproceso son locales: existen solo ahí adentro.

Cómo funciona en PSeInt:

  • Los SubProceso se escriben fuera del algoritmo principal, antes o después, pero no dentro.
  • PSeInt empieza ejecutando el Algoritmo principal. Los subprocesos no se ejecutan solos: solo cuando los llamás por su nombre.
  • Al llamar, los valores se copian en los parámetros (paso por valor). Si el subproceso modifica un parámetro, la variable original del algoritmo no cambia.
  • Una variable declarada dentro del subproceso es local: no existe afuera. Las del algoritmo principal son globales y se pueden ver desde los subprocesos, pero lo recomendable es pasar los datos como parámetros.
  • El nombre del subproceso se elige como el de una variable: sin espacios, descriptivo y sin coincidir con palabras reservadas.

Hay dos formas de escribir un subproceso según si recibe datos o no:

  • Sin parámetros: no recibe datos; siempre hace la misma tarea (mostrar un encabezado, un menú fijo). Se llama con paréntesis vacíos: MostrarEncabezado();.
  • Con parámetros: recibe uno o varios datos entre paréntesis y trabaja con ellos; el mismo subproceso sirve para valores distintos. Se llama pasando los valores: Saludar("Ana");.

A. Subprocesos sin parámetros

Se usan cuando la tarea es siempre igual y no necesita datos externos. El encabezado termina en el nombre del subproceso, sin paréntesis con parámetros. Pueden usar variables globales, pero lo más claro es que solo muestren o hagan una acción fija.

Ejemplo 1 · Sin parámetros

Sirve para tareas fijas y repetitivas, como mostrar un encabezado o un menú. 

SubProceso MostrarEncabezado
    Escribir "==============================";
    Escribir "     SISTEMA DE INVENTARIO    ";
    Escribir "==============================";
FinSubProceso

Algoritmo DemoEncabezado
    MostrarEncabezado();
    Escribir "Cargando datos...";
FinAlgoritmo
  • Líneas 1 a 5: definimos el procedimiento. Todavía no se ejecuta nada.
  • Línea 8: al llamarlo con MostrarEncabezado();, se ejecutan sus 3 líneas internas.

B. Subprocesos con parámetros

Se usan cuando el subproceso necesita datos para trabajar. Los parámetros se escriben entre paréntesis en el encabezado y se comportan como variables locales: reciben una copia del valor que se pasa en la llamada. Puede haber uno o varios, separados por comas.

Ejemplo 2 · Con un parámetro

El parámetro permite que el mismo procedimiento sirva para distintos datos. 

SubProceso Saludar(nombre)
    Escribir "¡Bienvenido/a, ", nombre, "!";
FinSubProceso

Algoritmo Demostracion
    Definir usuario Como Caracter;
    Escribir "Ingresá tu nombre:";
    Leer usuario;
    Saludar(usuario);   // Le pasamos el valor de la variable
FinAlgoritmo
  • Línea 1: nombre es el parámetro: recibe el dato que le enviamos.
  • Línea 8: el valor de usuario se copia dentro de nombre y se usa en el procedimiento.
Ejemplo 3 · Con varios parámetros

Ideal para tareas que combinan datos, como calcular e imprimir un recibo. 

SubProceso MostrarRecibo(producto, precio, cantidad)
    Definir total Como Real;   // Variable local
    total <- precio * cantidad;
    Escribir "Producto: ", producto;
    Escribir "Cantidad: ", cantidad, " x $", precio;
    Escribir "TOTAL: $", total;
FinSubProceso

Algoritmo DemoRecibo
    MostrarRecibo("Cuaderno", 250.50, 3);
    MostrarRecibo("Lápiz", 80.00, 5);
FinAlgoritmo
  • Línea 2: total es local: solo existe dentro del procedimiento.
  • Líneas 9 y 10: reutilizamos el mismo procedimiento con datos distintos. Eso es modularizar.
Ejemplo 4 · Programa completo

Un programa real combina varios procedimientos y los llama desde el algoritmo principal. 

SubProceso MostrarMenu
    Escribir "1. Saludar";
    Escribir "2. Mostrar despedida";
    Escribir "0. Salir";
FinSubProceso

SubProceso Saludar(nombre)
    Escribir "Hola, ", nombre, ". ¡Buen día!";
FinSubProceso

SubProceso Despedir(nombre)
    Escribir "Hasta luego, ", nombre, ". ¡Éxitos!";
FinSubProceso

Algoritmo DemoMenu
    Definir opcion Como Entero;
    Definir usuario Como Caracter;

    Escribir "Ingresá tu nombre:";
    Leer usuario;

    Mientras opcion <> 0 Hacer
        MostrarMenu();
        Leer opcion;

        Si opcion = 1 Entonces
            Saludar(usuario);
        Sino
            Si opcion = 2 Entonces
                Despedir(usuario);
            FinSi
        FinSi
    FinMientras

    Escribir "Programa finalizado.";
FinAlgoritmo
  • Líneas 1 a 14: tres procedimientos independientes, cada uno con una responsabilidad.
  • Línea 21: el algoritmo principal orquesta las llamadas; no repite el código de cada acción.
  • Línea 23: el bucle mantiene el menú activo hasta elegir 0.
🔍 Sin parámetros vs. con parámetros:
  • Sin parámetros: SubProceso MostrarMenu siempre muestra lo mismo.
  • Con parámetros: SubProceso Saludar(nombre) cambia según el dato recibido.
  • Llamada: MostrarMenu(); no lleva datos; Saludar("Ana"); sí.
  • Los parámetros son locales: existen solo dentro del subproceso.
💡 Diferencia rápida: un procedimiento hace algo y no devuelve nada. Una función (también subproceso, pero con retorno) calcula un valor y lo devuelve. En PSeInt se declara SubProceso resultado <- Nombre(...) cuando retorna.

Ejemplo de función que devuelve un valor:

SubProceso doble <- CalcularDoble(numero)
    doble <- numero * 2;
FinSubProceso

Algoritmo DemoFuncion
    Definir n, resultado Como Entero;
    Escribir "Ingresá un número:";
    Leer n;
    resultado <- CalcularDoble(n);   // la función devuelve el doble
    Escribir "El doble es: ", resultado;
FinAlgoritmo
  • Línea 1: la parte izquierda de la flecha indica qué variable devuelve la función.
  • Línea 2: dentro del subproceso se asigna el resultado a esa variable de retorno.
  • Línea 9: la llamada se usa en una asignación porque produce un valor; un procedimiento, en cambio, se llama solo: MostrarMenu();.

Procedimiento vs. función:

  • Procedimiento: ejecuta acciones y no devuelve nada. Se llama como una instrucción: Saludar("Ana");
  • Función: calcula y devuelve un valor. Se usa dentro de una expresión o asignación: resultado <- CalcularDoble(5);
  • Ambos se declaran con SubProceso y se cierran con FinSubProceso.

Buenas prácticas:

  • Un subproceso, una responsabilidad: mostrá un menú, calculá un total o validá un dato, pero no todo junto.
  • Usá nombres claros: MostrarMenu, CalcularPromedio, ValidarEdad.
  • Pasá los datos como parámetros en lugar de depender de variables globales.
  • No pongas Leer dentro de un subproceso si el dato lo necesita el algoritmo principal: es más claro leer afuera y pasar el valor.
  • Mantené el algoritmo principal corto: que orqueste llamadas y no repita la lógica que ya está dentro de cada subproceso.

Errores comunes con subprocesos:

  • Definirlo pero no llamarlo: el código existe, pero nunca se ejecuta.
  • Olvidar FinSubProceso o cerrarlo con FinAlgoritmo.
  • Pasar una cantidad distinta de argumentos a la de parámetros declarados.
  • Usar una variable local fuera del subproceso: no existe en el algoritmo principal.
  • Confundir parámetro con variable local: el parámetro llega con un valor desde la llamada; la variable local se declara adentro.
  • Llamar a una función como si fuera procedimiento o ignorar el valor que devuelve.

    Desafío Práctico Integrador

    Un único problema que obliga a usar todos los conceptos de la Sección 1.

    🎬 El Sistema de Control del Cine

    Desarrollá un sistema en PSeInt para administrar las ventas del día de una sala de cine de barrio. El programa debe cumplir estos requisitos:

    1. Usar un Subproceso para mostrar un encabezado de bienvenida.
    2. Preguntar al cajero cuántos clientes se van a procesar y recorrerlos con un bucle Para.
    3. Para cada cliente, Leer la edad y el precio base de la entrada.
    4. Aplicar un Condicional: si el cliente tiene menos de 12 años, recibe 50% de descuento (entrada infantil); si no, paga tarifa completa.
    5. Usar un Contador para rastrear cuántos niños aprovecharon la promoción.
    6. Usar un Acumulador para calcular el total recaudado en caja.
    7. Usar un bucle Mientras para validar que la edad no sea negativa; si lo es, pedirla de nuevo.
    💡 Tip: antes de escribir código, anotá en papel qué variable cumple cada rol (¿cuál es contador?, ¿cuál acumulador?) y qué estructura resuelve cada requisito.

    Código de Solución

    Solución completa, indentada y comentada. Comparala con la tuya después de intentarlo.

    // Subproceso que actúa como procedimiento de diseño visual
SubProceso MostrarEncabezado
    Escribir "========================================";
    Escribir "      SISTEMA DE CONTROL DE CINE       ";
    Escribir "========================================";
FinSubProceso

Algoritmo ControlCine
    // Declaración de variables
    Definir cantClientes, i, edad Como Entero;
    Definir precioBase, precioFinal, totalRecaudado Como Real;
    Definir contadorNinos Como Entero;

    // Inicialización de contador y acumulador
    totalRecaudado <- 0;
    contadorNinos <- 0;

    // Llamada al procedimiento inicial
    MostrarEncabezado();

    Escribir "Ingrese la cantidad de clientes a procesar hoy:";
    Leer cantClientes;

    // Bucle PARA: número fijo de iteraciones
    Para i <- 1 Hasta cantClientes Con Paso 1 Hacer
        Escribir "";
        Escribir "--- Procesando Cliente ", i, " de ", cantClientes, " ---";

        Escribir "Ingrese el precio base de la entrada:";
        Leer precioBase;

        Escribir "Ingrese la edad del cliente:";
        Leer edad;

        // Bucle MIENTRAS: validación de datos erróneos
        Mientras edad < 0 Hacer
            Escribir "Error: la edad no puede ser negativa. Ingrese nuevamente:";
            Leer edad;
        FinMientras

        // Condicional: descuento para menores de 12
        Si edad < 12 Entonces
            precioFinal <- precioBase * 0.50;   // Aplica 50% de descuento
            Escribir "Cliente califica como NIÑO. Descuento del 50% aplicado.";
            contadorNinos <- contadorNinos + 1; // Contador
        Sino
            precioFinal <- precioBase;          // Tarifa completa
            Escribir "Cliente paga tarifa de ADULTO.";
        FinSi

        Escribir "Monto a pagar por este cliente: $", precioFinal;

        totalRecaudado <- totalRecaudado + precioFinal; // Acumulador
    FinPara

    // Reporte final
    Escribir "";
    Escribir "========================================";
    Escribir "           REPORTE DE CIERRE           ";

    1. ¿Qué es la programación estructurada?

    • A) Escribir la mayor cantidad de código posible, sin importar el orden.
    • B) Organizar el programa con solo tres estructuras: secuencia, selección e iteración.
    • C) Programar únicamente con subprocesos y sin variables.
    • D) Evitar los bucles para que el programa sea más corto.
    ✔ Correcta: B. La programación estructurada se apoya en secuencia (una instrucción tras otra), selección (Si) e iteración (Mientras / Para).

    2. ¿Qué significa declarar una variable en PSeInt?

    • A) Asignarle obligatoriamente un valor inicial.
    • B) Indicar su nombre y su tipo de dato antes de usarla.
    • C) Mostrarla en pantalla con Escribir.
    • D) Convertirla en una constante que no puede cambiar.
    ✔ Correcta: B. Declarar es reservar el espacio e indicar el tipo (Definir edad Como Entero;). El valor se asigna después con <-.

    3. ¿Cuál es la diferencia entre un contador y un acumulador?

    • A) El contador solo funciona con números reales y el acumulador con enteros.
    • B) El contador cambia por un valor fijo (normalmente 1); el acumulador cambia por valores variables.
    • C) El acumulador se usa solo en condicionales y el contador solo en subprocesos.
    • D) Son exactamente lo mismo, solo cambia el nombre.
    ✔ Correcta: B. Contador: c <- c + 1. Acumulador: suma <- suma + valor, donde valor puede cambiar en cada vuelta.

    4. ¿Cuándo conviene usar Mientras y cuándo Para?

    • A) Mientras: no se sabe cuántas vueltas habrá. Para: se conoce el número exacto de vueltas.
    • B) Para: no se sabe cuántas vueltas habrá. Mientras: se conoce el número exacto.
    • C) Mientras solo sirve para sumar y Para solo para restar.
    • D) Los dos son equivalentes y se eligen al azar.
    ✔ Correcta: A. Un menú que termina cuando el usuario elige "Salir" pide Mientras; procesar 10 alumnos pide Para.

    5. Si la condición de un bucle Mientras es falsa desde la primera vuelta, ¿qué ocurre?

    • A) El bloque se ejecuta una vez de todos modos.
    • B) El bloque no se ejecuta nunca.
    • C) PSeInt muestra un error de sintaxis.
    • D) El bucle se ejecuta infinitamente.
    ✔ Correcta: B. El Mientras evalúa antes de entrar; si la condición es falsa, el bloque se saltea. El infinito aparece cuando la condición nunca deja de ser verdadera.

    6. ¿Por qué es importante inicializar en 0 un acumulador?

    • A) Para que la suma empiece desde una base numérica conocida y no arrastre basura.
    • B) Porque PSeInt no permite declarar variables sin inicializar.
    • C) Para que el programa tarde más en ejecutarse.
    • D) No hace falta: PSeInt lo inicializa solo en 1.
    ✔ Correcta: A. Si el acumulador arranca vacío, la primera suma no tiene un valor base y el resultado es incorrecto o genera error.

    7. ¿Qué dos ventajas aporta dividir un programa en subprocesos?

    • A) Hace el programa más largo y difícil de leer.
    • B) Permite reutilizar código y facilita la lectura y el mantenimiento.
    • C) Elimina la necesidad de declarar variables.
    • D) Impide usar bucles dentro del programa.
    ✔ Correcta: B. Cada subproceso tiene una responsabilidad; si hay que cambiar algo, se modifica en un solo lugar y se puede llamar varias veces.

    8. ¿Qué diferencia hay entre un procedimiento sin parámetros y uno con parámetros?

    • A) El sin parámetros sirve para tareas fijas (un menú); el con parámetros recibe datos para trabajar (saludar a una persona).
    • B) El sin parámetros recibe datos y el con parámetros no recibe nada.
    • C) Ninguno de los dos puede mostrar texto en pantalla.
    • D) Son iguales: los parámetros son opcionales y no cambian nada.
    ✔ Correcta: A. MostrarMenu() no necesita datos; Saludar(nombre) sí, porque el mensaje cambia según quién sea la persona.

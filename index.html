1 Programación Estructurada

Es una forma de escribir programas usando solo tres estructuras de control: secuencia (una instrucción tras otra), selección (decidir con condiciones) e iteración (repetir con bucles). Se usa porque evita el desorden y hace que el código sea fácil de leer, mantener y corregir.

Esquema mental Secuencia → Selección → Iteración

2 Variables

Una variable es un contenedor en la memoria donde guardamos un dato que puede cambiar durante el programa. En PSeInt hay que declarar su tipo antes de usarla.

Tipos habituales: Entero, Real, Caracter (para texto) y Logico.

Sintaxis Definir nombre_variable Como Tipo_De_Dato; 
Algoritmo EjemploVariable
    Definir edad Como Entero;   // Declara la variable para números enteros
    edad <- 20;                    // Asigna el valor 20 a la variable
    Escribir "Tu edad es: ", edad;
FinAlgoritmo
  • Línea 2: creamos el contenedor edad, apto solo para enteros.
  • Línea 3: con la flecha de asignación (<-) guardamos 20 dentro de edad.
  • Línea 4: mostramos un mensaje combinando texto y el valor de la variable.

✍️ Ejercicio: tres variables

Declará tres variables: nombre (Caracter), edad (Entero) y altura (Real). Asignales un valor a cada una y mostralas con Escribir.

3 Leer y Escribir

Son los comandos de Entrada/Salida. Escribir muestra información en pantalla y Leer pausa el programa para capturar un dato del teclado. Son lo primero que necesitás para que un programa "hable" con el usuario. 

Algoritmo EntradaSalida
    Definir nombre Como Caracter;
    Escribir "Escribe tu nombre:";
    Leer nombre;                       // Guarda lo que el usuario tipea
    Escribir "Hola, ", nombre;
FinAlgoritmo
  • Línea 3: envía un mensaje visual al usuario.
  • Línea 4: pausa la ejecución y guarda la respuesta del teclado en nombre.

✍️ Ejercicio: pedir y mostrar

Pedile al usuario su ciudad y mostrá el mensaje Vivís en <ciudad>. Usá Leer para capturar el dato y luego Escribir para mostrarlo.

4 Condicionales (Si–Entonces)

Un condicional permite decidir: si la condición es verdadera se ejecuta un camino; si es falsa (Sino), se ejecuta otro. Es el corazón de la selección.

Sintaxis Si condición Entonces
    // código si es verdadero
Sino
    // código si es falso
FinSi 
Algoritmo EjemploCondicional
    Definir nota Como Real;
    nota <- 7.5;
    Si nota >= 6.0 Entonces
        Escribir "Aprobado";
    Sino
        Escribir "Desaprobado";
    FinSi
FinAlgoritmo
  • Línea 4: evalúa si nota (7.5) es mayor o igual a 6.0.
  • Línea 5: al ser verdadero, ejecuta esa línea y salta al final de la estructura.

✍️ Ejercicio: mayor o menor de edad

Leé la edad de una persona. Si es mayor o igual a 18, mostrá "Mayor de edad"; si no, mostrá "Menor de edad". Usá Si … Entonces … Sino … FinSi.

5 Bucle Mientras

Repite un bloque mientras una condición sea verdadera. Si la condición es falsa desde el inicio, el bucle nunca se ejecuta. Útil cuando no sabemos cuántas vueltas hará el usuario.

Sintaxis Mientras condición Hacer
    // código a repetir
FinMientras 
Algoritmo EjemploMientras
    Definir opcion Como Entero;
    opcion <- 1;
    Mientras opcion != 0 Hacer
        Escribir "Para salir presiona 0, para continuar cualquier número:";
        Leer opcion;
    FinMientras
FinAlgoritmo
  • Línea 4: revisa si opcion es distinto de 0. Como vale 1, entra al bucle.
  • Línea 6: pide un nuevo valor. El bucle se repetirá hasta que el usuario escriba 0.

✍️ Ejercicio: contar hasta 5

Mostrá los números del 1 al 5 usando un bucle Mientras. No olvides incrementar la variable dentro del bucle para que no se repita infinitamente.

6 Bucle Para (For)

Repite un bloque un número exacto y conocido de veces. Controla automáticamente el inicio, el fin y el paso del contador.

Sintaxis Para variable <- inicio Hasta fin Con Paso incremento Hacer
    // código a repetir
FinPara 
Algoritmo EjemploPara
    Definir i Como Entero;
    Para i <- 1 Hasta 3 Con Paso 1 Hacer
        Escribir "Vuelta número: ", i;
    FinPara
FinAlgoritmo
  • Línea 3: inicializa i en 1, se detiene al superar 3 y avanza de 1 en 1.
  • Línea 4: imprime el número de la iteración actual.

✍️ Ejercicio: pares del 2 al 10

Mostrá los números pares del 2 al 10 usando un bucle Para. Podés usar Con Paso 2 o recorrer todo y filtrar con Si + MOD.

7 Contador

Un contador aumenta o disminuye su valor en una cantidad fija (normalmente 1). Sirve para saber cuántas veces ocurre un evento. Se usa mucho dentro de bucles.

Fórmula clásica contador <- contador + 1; 
Algoritmo EjemploContador
    Definir c Como Entero;
    c <- 0;          // Inicialización obligatoria
    c <- c + 1;      // Ahora vale 1
    c <- c + 1;      // Ahora vale 2
    Escribir "Contador: ", c;
FinAlgoritmo
  • Línea 3: el conteo empieza en 0.
  • Líneas 4 y 5: sumamos 1 a su propio valor actual, de forma consecutiva.

✍️ Ejercicio: contar mayores a 5

Recorré los números del 1 al 10 y contá cuántos son mayores a 5. Mostrá el resultado final con Escribir.

8 Acumulador

Un acumulador cambia por cantidades variables. Se usa para calcular sumas totales: total de una caja, suma de notas, gastos del mes, etc.

Fórmula clásica acumulador <- acumulador + variable_o_valor; 
Algoritmo EjemploAcumulador
    Definir suma, precio Como Real;
    suma <- 0;              // Inicialización obligatoria
    precio <- 15.50;
    suma <- suma + precio;  // Suma el precio variable
    Escribir "Total acumulado: ", suma;
FinAlgoritmo
  • Línea 3: el acumulador arranca limpio en 0.
  • Línea 5: suma el contenido de precio (15.50) a lo que ya tenía suma.

✍️ Ejercicio: sumar del 1 al 10

Sumá los números del 1 al 10 usando un acumulador y mostrá el total final. Recordá inicializar el acumulador en 0.

9 Subprocesos / Procedimientos

Un subproceso es un bloque de código con nombre propio que realiza una tarea específica. El procedimiento es un subproceso que NO devuelve un valor: solo ejecuta acciones (mostrar un menú, imprimir un recibo, validar datos). Se usa para modularizar: dividir un programa grande en piezas chicas, reutilizables y fáciles de leer.

Sintaxis general SubProceso NombreDelProcedimiento (parámetro1, parámetro2)
    // acciones del procedimiento
FinSubProceso

// Para usarlo (llamarlo):
NombreDelProcedimiento(valor1, valor2);
⚠️ Idea clave: los parámetros son los datos que le "pasás" al procedimiento entre paréntesis. Un procedimiento puede tener 0, 1 o varios parámetros. Las variables declaradas dentro del subproceso son locales: existen solo ahí adentro.
Ejemplo A · Sin parámetros

Sirve para tareas fijas y repetitivas, como mostrar un encabezado o un menú. 

SubProceso MostrarEncabezado
    Escribir "==============================";
    Escribir "     SISTEMA DE INVENTARIO    ";
    Escribir "==============================";
FinSubProceso

Algoritmo DemoEncabezado
    MostrarEncabezado();
    Escribir "Cargando datos...";
FinAlgoritmo
  • Líneas 1 a 5: definimos el procedimiento. Todavía no se ejecuta nada.
  • Línea 8: al llamarlo con MostrarEncabezado();, se ejecutan sus 3 líneas internas.
Ejemplo B · Con un parámetro

El parámetro permite que el mismo procedimiento sirva para distintos datos. 

SubProceso Saludar(nombre)
    Escribir "¡Bienvenido/a, ", nombre, "!";
FinSubProceso

Algoritmo Demostracion
    Definir usuario Como Caracter;
    Escribir "Ingresá tu nombre:";
    Leer usuario;
    Saludar(usuario);   // Le pasamos el valor de la variable
FinAlgoritmo
  • Línea 1: nombre es el parámetro: recibe el dato que le enviamos.
  • Línea 8: el valor de usuario se copia dentro de nombre y se usa en el procedimiento.
Ejemplo C · Con varios parámetros

Ideal para tareas que combinan datos, como calcular e imprimir un recibo. 

SubProceso MostrarRecibo(producto, precio, cantidad)
    Definir total Como Real;   // Variable local
    total <- precio * cantidad;
    Escribir "Producto: ", producto;
    Escribir "Cantidad: ", cantidad, " x $", precio;
    Escribir "TOTAL: $", total;
FinSubProceso

Algoritmo DemoRecibo
    MostrarRecibo("Cuaderno", 250.50, 3);
    MostrarRecibo("Lápiz", 80.00, 5);
FinAlgoritmo
  • Línea 2: total es local: solo existe dentro del procedimiento.
  • Líneas 9 y 10: reutilizamos el mismo procedimiento con datos distintos. Eso es modularizar.
Ejemplo D · Programa completo

Un programa real combina varios procedimientos y los llama desde el algoritmo principal. 

SubProceso MostrarMenu
    Escribir "1. Saludar";
    Escribir "2. Mostrar despedida";
    Escribir "0. Salir";
FinSubProceso

SubProceso Saludar(nombre)
    Escribir "Hola, ", nombre, ". ¡Buen día!";
FinSubProceso

SubProceso Despedir(nombre)
    Escribir "Hasta luego, ", nombre, ". ¡Éxitos!";
FinSubProceso

Algoritmo DemoMenu
    Definir opcion Como Entero;
    Definir usuario Como Caracter;

    Escribir "Ingresá tu nombre:";
    Leer usuario;

    Mientras opcion != 0 Hacer
        MostrarMenu();
        Leer opcion;

        Si opcion == 1 Entonces
            Saludar(usuario);
        Sino
            Si opcion == 2 Entonces
                Despedir(usuario);
            FinSi
        FinSi
    FinMientras

    Escribir "Programa finalizado.";
FinAlgoritmo
  • Líneas 1 a 14: tres procedimientos independientes, cada uno con una responsabilidad.
  • Línea 21: el algoritmo principal orquesta las llamadas; no repite el código de cada acción.
  • Línea 23: el bucle mantiene el menú activo hasta elegir 0.
💡 Diferencia rápida: un procedimiento hace algo y no devuelve nada. Una función (también subproceso, pero con retorno) calcula un valor y lo devuelve. En PSeInt se declara SubProceso resultado <- Nombre(...) cuando retorna.

    1. ¿Cuál es la diferencia técnica fundamental entre un contador y un acumulador?

    • A) El contador se usa solo en bucles Para y el acumulador en bucles Mientras.
    • B) El contador cambia por un valor constante fijo, mientras que el acumulador cambia por valores variables.
    • C) El acumulador solo suma enteros y el contador puede contar decimales.
    • D) No existe ninguna diferencia, son términos idénticos.
    ✔ Correcta: B. El contador incrementa en un paso fijo (c <- c + 1), mientras que el acumulador recibe valores dinámicos (suma <- suma + valor).

    2. Si necesitás un menú donde el usuario decida cuándo salir presionando la opción 9, ¿qué estructura es la más adecuada?

    • A) Un bucle Para (For).
    • B) Una estructura Si-Entonces.
    • C) Un bucle Mientras.
    • D) Un Subproceso aislado.
    ✔ Correcta: C. El bucle Mientras es ideal cuando no sabemos cuántas vueltas dará el usuario antes de querer salir.

    3. ¿Qué sucede si no inicializás un contador (c <- 0) antes de usarlo en c <- c + 1 en PSeInt?

    • A) PSeInt asume automáticamente que vale 10.
    • B) El programa lanza un error de variable no inicializada.
    • C) El programa ignora la línea y continúa.
    • D) El contador se convierte automáticamente en texto.
    ✔ Correcta: B. En PSeInt estricto, sumar a una variable vacía genera un error porque no posee un valor numérico base.

    4. El bucle Para se diferencia del bucle Mientras principalmente en que:

    • A) El bucle Para evalúa condiciones lógicas complejas con Y/O.
    • B) El bucle Para se ejecuta de manera indeterminada hasta un error.
    • C) El bucle Para conoce de antemano el número exacto de iteraciones.
    • D) El bucle Para no requiere una variable de control.
    ✔ Correcta: C. El ciclo Para es determinado (sabemos inicio y fin); Mientras es indeterminado (depende de una condición cambiante).

    5. Un procedimiento (Subproceso sin retorno) se utiliza principalmente para:

    • A) Realizar un cálculo matemático complejo y obligatoriamente regresar un número real.
    • B) Declarar todas las variables globales del algoritmo principal.
    • C) Reemplazar por completo el uso de bucles condicionales.
    • D) Modularizar tareas repetitivas de interacción o lógica que no necesitan retornar un valor.
    ✔ Correcta: D. Los procedimientos ejecutan acciones de forma autónoma (mostrar un menú, formatear textos) y mejoran la legibilidad sin devolver variables.

    Desafío Práctico Integrador

    Un único problema que obliga a usar todos los conceptos de la Sección 1.

    🎬 El Sistema de Control del Cine

    Desarrollá un sistema en PSeInt para administrar las ventas del día de una sala de cine de barrio. El programa debe cumplir estos requisitos:

    1. Usar un Subproceso para mostrar un encabezado de bienvenida.
    2. Preguntar al cajero cuántos clientes se van a procesar y recorrerlos con un bucle Para.
    3. Para cada cliente, Leer la edad y el precio base de la entrada.
    4. Aplicar un Condicional: si el cliente tiene menos de 12 años, recibe 50% de descuento (entrada infantil); si no, paga tarifa completa.
    5. Usar un Contador para rastrear cuántos niños aprovecharon la promoción.
    6. Usar un Acumulador para calcular el total recaudado en caja.
    7. Usar un bucle Mientras para validar que la edad no sea negativa; si lo es, pedirla de nuevo.
    💡 Tip: antes de escribir código, anotá en papel qué variable cumple cada rol (¿cuál es contador?, ¿cuál acumulador?) y qué estructura resuelve cada requisito.

    Código de Solución

    Solución completa, indentada y comentada. Comparala con la tuya después de intentarlo.

    // Subproceso que actúa como procedimiento de diseño visual
SubProceso MostrarEncabezado
    Escribir "========================================";
    Escribir "      SISTEMA DE CONTROL DE CINE       ";
    Escribir "========================================";
FinSubProceso

Algoritmo ControlCine
    // Declaración de variables
    Definir cantClientes, i, edad Como Entero;
    Definir precioBase, precioFinal, totalRecaudado Como Real;
    Definir contadorNinos Como Entero;

    // Inicialización de contador y acumulador
    totalRecaudado <- 0;
    contadorNinos <- 0;

    // Llamada al procedimiento inicial
    MostrarEncabezado();

    Escribir "Ingrese la cantidad de clientes a procesar hoy:";
    Leer cantClientes;

    // Bucle PARA: número fijo de iteraciones
    Para i <- 1 Hasta cantClientes Con Paso 1 Hacer
        Escribir "";
        Escribir "--- Procesando Cliente ", i, " de ", cantClientes, " ---";

        Escribir "Ingrese el precio base de la entrada:";
        Leer precioBase;

        Escribir "Ingrese la edad del cliente:";
        Leer edad;

        // Bucle MIENTRAS: validación de datos erróneos
        Mientras edad < 0 Hacer
            Escribir "Error: la edad no puede ser negativa. Ingrese nuevamente:";
            Leer edad;
        FinMientras

        // Condicional: descuento para menores de 12
        Si edad < 12 Entonces
            precioFinal <- precioBase * 0.50;   // Aplica 50% de descuento
            Escribir "Cliente califica como NIÑO. Descuento del 50% aplicado.";
            contadorNinos <- contadorNinos + 1; // Contador
        Sino
            precioFinal <- precioBase;          // Tarifa completa
            Escribir "Cliente paga tarifa de ADULTO.";
        FinSi

        Escribir "Monto a pagar por este cliente: $", precioFinal;

        totalRecaudado <- totalRecaudado + precioFinal; // Acumulador
    FinPara

    // Reporte final
    Escribir "";
    Escribir "========================================";
    Escribir "           REPORTE DE CIERRE           ";
    Escribir "========================================";
    Escribir "Cantidad de niños con descuento: ", contadorNinos;
    Escribir "Total recaudado en caja: $", totalRecaudado;
    Escribir "========================================";
    Escribir "Proceso finalizado con éxito.";
FinAlgoritmo

    1. ¿Qué es la programación estructurada?

    • A) Escribir la mayor cantidad de código posible, sin importar el orden.

    2. ¿Qué significa declarar una variable en PSeInt?

    • A) Asignarle obligatoriamente un valor inicial.
    • B) Indicar su nombre y su tipo de dato antes de usarla.
    • C) Mostrarla en pantalla con Escribir.
    • D) Convertirla en una constante que no puede cambiar.
    ✔ Correcta: B. Declarar es reservar el espacio e indicar el tipo (Definir edad Como Entero;). El valor se asigna después con <-.

    3. ¿Cuál es la diferencia entre un contador y un acumulador?

    • A) El contador solo funciona con números reales y el acumulador con enteros.
    • B) El contador cambia por un valor fijo (normalmente 1); el acumulador cambia por valores variables.
    • C) El acumulador se usa solo en condicionales y el contador solo en subprocesos.
    • D) Son exactamente lo mismo, solo cambia el nombre.
    ✔ Correcta: B. Contador: c <- c + 1. Acumulador: suma <- suma + valor, donde valor puede cambiar en cada vuelta.

    4. ¿Cuándo conviene usar Mientras y cuándo Para?

    • A) Mientras: no se sabe cuántas vueltas habrá. Para: se conoce el número exacto de vueltas.
    • B) Para: no se sabe cuántas vueltas habrá. Mientras: se conoce el número exacto.
    • C) Mientras solo sirve para sumar y Para solo para restar.
    • D) Los dos son equivalentes y se eligen al azar.
    ✔ Correcta: A. Un menú que termina cuando el usuario elige "Salir" pide Mientras; procesar 10 alumnos pide Para.

    5. Si la condición de un bucle Mientras es falsa desde la primera vuelta, ¿qué ocurre?

    • A) El bloque se ejecuta una vez de todos modos.
    • B) El bloque no se ejecuta nunca.
    • C) PSeInt muestra un error de sintaxis.
    • D) El bucle se ejecuta infinitamente.
    ✔ Correcta: B. El Mientras evalúa antes de entrar; si la condición es falsa, el bloque se saltea. El infinito aparece cuando la condición nunca deja de ser verdadera.

    6. ¿Por qué es importante inicializar en 0 un acumulador?

    • A) Para que la suma empiece desde una base numérica conocida y no arrastre basura.
    • B) Porque PSeInt no permite declarar variables sin inicializar.
    • C) Para que el programa tarde más en ejecutarse.
    • D) No hace falta: PSeInt lo inicializa solo en 1.
    ✔ Correcta: A. Si el acumulador arranca vacío, la primera suma no tiene un valor base y el resultado es incorrecto o genera error.

    7. ¿Qué dos ventajas aporta dividir un programa en subprocesos?

    • A) Hace el programa más largo y difícil de leer.
    • B) Permite reutilizar código y facilita la lectura y el mantenimiento.
    • C) Elimina la necesidad de declarar variables.
    • D) Impide usar bucles dentro del programa.
    ✔ Correcta: B. Cada subproceso tiene una responsabilidad; si hay que cambiar algo, se modifica en un solo lugar y se puede llamar varias veces.

    8. ¿Qué diferencia hay entre un procedimiento sin parámetros y uno con parámetros?

    • A) El sin parámetros sirve para tareas fijas (un menú); el con parámetros recibe datos para trabajar (saludar a una persona).
    • B) El sin parámetros recibe datos y el con parámetros no recibe nada.
    • C) Ninguno de los dos puede mostrar texto en pantalla.
    • D) Son iguales: los parámetros son opcionales y no cambian nada.
    ✔ Correcta: A. MostrarMenu() no necesita datos; Saludar(nombre) sí, porque el mensaje cambia según quién sea la persona.
